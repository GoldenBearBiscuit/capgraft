## 1. 原始想法

> 「我有一个想法，就是结合 REA 那种逆向，还有 schlarevolve 那种吸收的概念，做一个可以不断扩展自己功能边界的开源项目。」

决策：MVP 聚焦「吸收闭环」本身——逆向产出候选、门禁决定放行、证据支撑回滚。自动逆向 / LLM 分析层明确推迟，候选先由人或 agent 手工产出。

落点：friction → candidate → publish → activate → known_good → invoke → verify / rollback。

## 2. coevo PRD：抽出 MVP 概念

> 「这是另一个作者的想法，我感觉我们有共性，能不能给我抽出一个 mvp 级别的概念设计。」

吸收：

- **概念守恒**：核心概念不随吸收自动生长，MVP 字段集严格封闭。
- **摩擦门禁**：每次增长必须回溯具体摩擦事件，`friction_id` 必填。
- **外部类型隔离**：外部项目的类型与依赖关在单文件 adapter 内，核心只认契约。

未吸收：完整概念演化代数等超出 MVP 规模的部分。

落点：`validate_spec` 严格字段校验、`capability.json` schema、单文件 `adapter.py`。

## 3. 热备 PRD：回滚机制复用

> 「还有一个是回滚机制，给你的 prd 是另一个作者设计的热备机制，你看下有没有能用上的。」

吸收：

- **不可变发布**：版本目录一经发布禁止覆盖。
- **原子切换**：同目录临时文件 + `os.replace`，读方永远看到完整 JSON。
- **known_good 状态**：保留最后已知可用版本作为回退目标。
- **追加式审计**：事件只追加，历史不更新不删除。
- **Worker 子进程隔离**：崩溃与挂死不影响主进程（明确不是安全沙箱）。

未吸收：多机热备、流量调度——单机 MVP 不需要。

关键决策：回滚恢复**完整旧注册表**，不删候选版本、不截断日志，回滚事件引用失败 run 与恢复目标。

落点：`publish` / `activate` / `rollback` / `_atomic_write_json` / `journal.jsonl` / `_call_worker`。

## 4. 实现约束

> 「行，开始写吧，然后我理解是 py 语言，产出的代码风格尽量统一，注释尽量全。」

决策：Python 纯标准库、单文件 CLI、中文注释统一风格；unittest 端到端测试用真实 Worker 子进程，不 mock；刻意的能力上限用 `# ponytail:` 标注（如单写者、并发激活需文件锁）。

## 5. QTrail PRD：质量链路吸纳

> 「等一下，这里是另一个人给我的工程 + 工艺的测试设计，看看有没有能吸纳进我项目的。」

吸收：

- **判断基于证据对象，不是状态字符串**：通过必须能追到某次 run 和它的产物。
- **候选自证与可信门禁分离**：AI 生成的材料不能自己决定自己通过。
- **不静默重试**：attempt 恒为 1，失败原样留痕。
- **可复现**：每个 run 带复现命令与环境快照。
- **来源标记**：测试用例标 `origin: human | agent`。

关键决策（堵自审批漏洞）：schema 1 的 smoke 由候选自带，等于候选自己给自己打分。升级为 **schema 2**（破坏性升级，不留兼容 shim）：移除 smoke，改为控制面 `trust --approver` 安装的受信任门禁；known_good 携带 `run_id + release_sha256`，发布字节偏离摘要时 invoke / verify / rollback 全部拒绝。端到端测试证明：候选篡改自身期望后 publish 仍通过，但 activate 必然失败并回滚。

未吸收：追溯索引、TIA 测试选择、flaky 生命周期、MCP 工具面——平台级规模，另行立项。

落点：`runs/` 证据、`trusted/` 门禁、`_check_known_good_digest`、5 个 E2E 用例。

## 6. 流程可视化

> 「把项目流程可视化，参考 infinite-map-zoom.html 这个文件的样式吧，里边主要是 zoom，没有流程那种箭头和线。」

决策：复用参考文件的暗绿终端风格与滚轮缩放交互，补上 SVG 贝塞尔箭头、人审 / 失败分支与证据存储道；12 节点 13 连线，几何校验无穿节点。

落点：`capgraft-flow.html`。

## 7. 代码视图与归档

> 「把整个项目的具体代码都挂到这个 ui 下，我好方便看。」

决策：构建期注入保持单文件离线——`build_code_view.py` 按节点映射注入源码快照，面板带行号 / 函数跳转 / 整文件切换；排除 HTML 自身避免递归膨胀。

落点：`build_code_view.py` + 流程页代码面板。

> 「把我的设计，包括其他人的设计，都打包到 docs 文件夹下，一起推上 git。」

决策：自有设计（概念设计 + 本演进记录）与外部输入（`references/` 原文归档、注明来源）一并入库推送。`concept-card.md` 为独立的技能设计，与 CapGraft 无关，按用户要求一并归档。
